# Choix natifs : copies de même nom — 8 octobre 2026

Les choix de cartes affichent désormais leur emplacement réel fourni par le moteur : Main, Cimetière, Terrain, bannissement, Extra Deck ou matériel Xyz ; les zones du Terrain indiquent leur numéro et leur position lorsque le prompt la fournit. Deux copies du même nom peuvent ainsi être distinguées sans modifier les indices, les réponses ni les règles du duel. Les anciennes sources classaient aussi les références du Cimetière et du Deck comme « Main » ; leur catégorie de présentation est maintenant exacte. Le véritable champ `overlay_sequence` différencie les matériels Xyz attachés et évite de les présenter comme des monstres sur le Terrain.

Le changement concerne `cardCandidate`, le libellé des retraits successifs de compteurs et `placeLabel` dans `NativeDuelDecisions.js`, avec le nouveau modèle de présentation pur `NativeDuelPresentationModel.js`. Les placements/condamnations emploient désormais EMZ/Pendule 1/2 plutôt que les anciennes séquences brutes 6/7 et 7/8 ; le numéro d’EMZ adverse est inversé conformément au plateau partagé. Les masques, zones natives et réponses restent inchangés. L’interface partagée utilise déjà ces libellés pour les choix multiples et les boutons AJOUTER/RETIRER ; l’intégration du libellé dans la branche de sélection simple de `main.js` est coordonnée et réalisée par root. Aucune disponibilité supplémentaire en mode strict n’est revendiquée et aucune règle de construction de Deck ne change.

## Parcours dans l’application

Le runner [audit-native-choice-locations-ui.py](../../scripts/audit-native-choice-locations-ui.py) joue réellement un Deck libre validé de 40 cartes. Un enregistrement local et un flux aléatoire déterministe varié précèdent le duel ; ensuite seules les actions visibles sont utilisées. Graceful Charity pioche trois cartes puis défausse deux Blue-Eyes choisis au clavier dans la Main. Monster Reborn propose ces deux copies au Cimetière, puis invoque réellement la copie choisie sur le plateau public. Le Deck sauvegardé reste identique.

Les deux parcours passent à **1440 × 900** et **390 × 844** ; Espace sélectionne les cartes, Entrée confirme et les boutons reflètent `aria-pressed`. Les six captures ont été inspectées : les libellés restent lisibles, reviennent à la ligne sur mobile et les options de cartes restent dans la largeur de l’écran avec des cibles d’au moins 44 px. Le premier préflight a montré un bouton de confirmation d’environ 34 px ; root a corrigé les deux boutons partagés avec la classe `decision-confirm-button` et une taille minimale de 44 px. Le préflight renforcé mesure réellement **44 px** pour les confirmations dans les deux tailles et les deux effets. [Rapport et captures après correction](artifacts/native-choice-locations-ui-2026-10-08/report.json) ; [captures historiques avant correction tactile](artifacts/native-choice-locations-ui-2026-10-08/preflight-before-touch-fix/report.json).

Ce **préflight** navigateur utilise l’application source via Vite avec `NODE_ENV=production` : le hook QA est absent et aucune API interne de jeu n’est appelée. Il ne certifie pas le bundle final ni la CSP de production. Les cibles cachées adverses, la propriété de la copie du Cimetière adverse, la numérotation inversée des EMZ, le détachement d’un matériel Xyz et le retrait réparti des compteurs sont certifiés séparément par les quatre scénarios WASM ; le parcours navigateur certifie les copies de la Main et du Cimetière propre. Les autres genres de prompts conservent leurs contrôles existants ; toutes leurs branches ne sont pas nouvellement certifiées ici.
